### H9 [needs_ingame_test] HeroUpdateHook invocation and pause/timeScale; where to sample

Poll inputs every Unity frame in the same Update (edge detection by comparing IsPressed with previous frame) and OR-accumulate a 'pressed since last sample' bitmask for frames. ### H10 [confirmed] Time.frameCount usability; time-scale distortions (FreezeMoment/hitstop)
Time.frameCount is safe and monotonic (the game itself uses it: `if (Time.frameCount % 10 == 0) Update10();`). Distortions: GameManager.FreezeMoment ramps Time.timeScale toward 0 via SetTimeScale; values below 0.01 are clamped to exactly 0. HeroController.TakeDamage starts gm.FreezeMoment(DAMAGE_FREEZE_DOWN, DAMAGE_FREEZE_WAIT, DAMAGE_FREEZE_UP, 0.0001f) => Time.timeScale == 0 during the hit freeze (same value as pause!). FreezeMoment(1) (0.04/0.03/0.04 s to 0) is also triggered on enemy kills (EnemyDeathEffects, HealthManager), levers, etc.; FreezeMoment(int type) presets 0..5 include type 2 = slow to 0.15 for 2 s. While TimeSlowed, PauseGameToggle yields break (can't pause). TimeController combines SlowMotionTimeScale * PauseTimeScale * PlatformBackgroundTimeScale * GenericTimeScale. Consequences: (a) never infer pause from timeScale==0 — use gm.isPaused / gameState==PAUSED; (b) t_game from unscaledDeltaTime counts hitstop as game time (ok, but record time_scale per frame so analysis can tell); (c) GameManager already has its own in-game clock: `public float PlayTime => sessionStartTime + sessionPlayTimer`, where IncreaseGameTimer adds unscaledDeltaTime only when gameState is PLAYING/ENTERING_LEVEL/EXITING_LEVEL and unscaledDeltaTime < 1 — this is the save's playTime semantic and worth logging alongside t_game.
